# Z01 Robot Assets · Z01 机器人仿真资产

MuJoCo / URDF simulation assets for the **Z01 humanoid robot** (Zvalley Robotics), covering the baseline model and the variants used for RoboCup humanoid development.

**Z01 人形机器人**（Zvalley Robotics）的 MuJoCo / URDF 仿真资产库，包含基线模型及 RoboCup 类人组开发所用的各变体。

## English

### Model variants

| Directory | Actuated joints | Description |
| --- | --- | --- |
| `Z01_std` | 29 | Baseline model: 2 × 7-DoF arms (shoulder ×3, elbow, wrist ×3), 3-DoF waist, 2 × 6-DoF legs (hip ×3, knee, ankle ×2) |
| `Z01_std_add_head` | 29 | `Z01_std` plus a 2-DoF head (`head_pitch` / `head_yaw`) and a camera mount; waist pitch/roll welded |
| `Z01_std_parallel_ankle` | 33 | Adds a parallel ankle linkage: per side, two rod joints (`ankle_1` / `ankle_2`) rigidly coupled to `ankle_pitch` / `ankle_roll` via tendon equality constraints. **Single source of truth for the robot body used in multi-robot scenes.** |
| `Z01_std_football_player` | 33 | Same robot as `parallel_ankle`, plus a RoboCup soccer-field scene (`xml/scene/soccer_field.xml`, `soccer_field_assets.xml`, `center_circle_ring.obj`) |
| `Z01_std_robocup` | 6 × 33 | Generated multi-robot scene: six `parallel_ankle` robots on one field, each with its own depth camera. See [`Z01_std_robocup/README.md`](Z01_std_robocup/README.md) |

### Repository layout

```
zv_robot_assets/
├── Z01_std/                     # baseline, 29 DoF
├── Z01_std_add_head/            # + 2-DoF head + camera
├── Z01_std_parallel_ankle/      # + parallel ankle linkage (tendon-coupled)
├── Z01_std_football_player/     # + RoboCup soccer field scene
└── Z01_std_robocup/             # 6-robot multi-agent scene (generated)
```

Each robot model directory follows the same layout:

```
<variant>/
├── urdf/            # URDF source model — the source of truth
├── xml/             # generated MuJoCo MJCF model (output — do not hand-edit)
├── meshes/          # STL/OBJ meshes (millimetre units, scaled 0.001 on import)
├── csv/             # joint & link tables: limits, effort, armature, inertia, mesh poses
└── urdf_to_xml.yaml # generation config: base height, per-pattern armature, motor rules, debug patches
```

### Generation pipeline

Everything under `xml/` is a **generated artifact**. To change a robot:

1. Edit the **URDF** (geometry, kinematics, inertia), the **CSV** (hand-measured parameters such as `armature`), or **`urdf_to_xml.yaml`** (base height, armature patterns, motor `ctrlrange` rules, decorative debug geoms appended via XPath patches).
2. Regenerate the MJCF with the converter from the companion simulation workspace (`robot_assets/utils/`). Never edit files under `xml/` by hand.

The `Z01_std_robocup` scene is generated by `robot_assets/utils/gen_robocup_multi_xml.py`:

```bash
python3 robot_assets/utils/gen_robocup_multi_xml.py          # regenerate main file + 6 robot fragments
python3 robot_assets/utils/gen_robocup_multi_xml.py --check  # validate only (names / joint addresses / frustum / loading)
```

### RoboCup scene — key figures

Verified by `gen_robocup_multi_xml.py --check`:

```
nq=247 nv=240 nu=174 ncam=6 ngeom=392
robot_01..06 base free joint qpos offsets: 0 / 40 / 80 / 120 / 160 / 200
soccer ball free joint:                    qpos = 240
```

- Each robot occupies 40 qpos (7 floating base + 33 joints); simulation code always resolves addresses **by name**, never by hard-coded offset.
- Field (RoboCup adult size): 14 m × 9 m, goals 2.6 m wide × 1.2 m high, centre circle r = 1.8 m. Ball spawns at field centre `(0, 0, 0.11)`.
- `<size njmax="4000" nconmax="2000"/>` is required for six humanoids colliding (~340 contacts observed); arena is ~900 MB **virtual** but only ~95 MB RSS.
- Compatible with MuJoCo **3.1.1**: per-robot submodels are duplicated via `<include>` merging, because `<attach>` / `<replicate>` require MuJoCo 3.2+ / 3.4+.

### Notes for downstream simulation packages

- `mj_sim` picks up models via `file(GLOB */xml/*.xml)`; after adding a model, re-run `colcon build --cmake-force-configure --packages-select mj_sim` so `robot_header/<model>.h` is regenerated.
- Design notes (why six `<include>` submodels, camera frustum sizing, arena memory behaviour, header-generator caveats) are documented in [`Z01_std_robocup/README.md`](Z01_std_robocup/README.md).

每个机器人模型目录结构一致：

```

```

### 生成流程

`xml/` 下的文件全部是**生成物**。修改机器人的正确方式：

1. 修改 **URDF**（几何、运动学、惯量）、**CSV**（手工实测参数，如 `armature`）或 **`urdf_to_xml.yaml`**（基座高度、分模式 armature、电机 `ctrlrange` 规则、经 XPath 追加的装饰调试几何）。
2. 用配套仿真工作区（`robot_assets/utils/`）的转换器重新生成 MJCF。不要手改 `xml/` 下的任何文件。

`Z01_std_robocup` 场景由 `robot_assets/utils/gen_robocup_multi_xml.py` 生成：

```bash
python3 robot_assets/utils/gen_robocup_multi_xml.py          # 重新生成（主文件 + 6 个机器人片段）
python3 robot_assets/utils/gen_robocup_multi_xml.py --check  # 只校验（重名 / 关节地址 / frustum / 加载）
```

### RoboCup 场景关键数字

由 `gen_robocup_multi_xml.py --check` 校验：

```
nq=247 nv=240 nu=174 ncam=6 ngeom=392
robot_01..06 基座 free joint qpos 偏移：0 / 40 / 80 / 120 / 160 / 200
足球 free joint：                        qpos = 240
```

- 每台机器人占 40 个 qpos（7 浮动基座 + 33 关节）；仿真代码一律**按名字查地址**，不假设偏移。
- 场地（RoboCup 成人组）：14 m × 9 m，球门宽 2.6 m、高 1.2 m，中圈半径 1.8 m；足球置于场心 `(0, 0, 0.11)`。
- 6 台人形互相碰撞必须放大 `<size njmax="4000" nconmax="2000"/>`（实测约 340 个接触）；arena 约 900 MB **虚拟**内存，但 RSS 仅约 95 MB。
- 兼容 MuJoCo **3.1.1**：6 台机器人通过 `<include>` 合并各自完整子模型实现复用（`<attach>` / `<replicate>` 需要 3.2+ / 3.4+）。

### 下游仿真包注意事项

- `mj_sim` 通过 `file(GLOB */xml/*.xml)` 收集模型；新增模型后需执行 `colcon build --cmake-force-configure --packages-select mj_sim` 重新生成 `robot_header/<model>.h`。
- 设计说明（为何拆成 6 个 `<include>` 子模型、深度相机 frustum、arena 内存表现、header 生成器注意事项）见 [`Z01_std_robocup/README.md`](Z01_std_robocup/README.md)。
